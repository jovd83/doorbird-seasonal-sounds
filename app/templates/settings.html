{{ icon("ext", 16) }}Triggering from another system

Whatever already knows a ring happened — a home-automation controller, an existing doorbell integration, a script — just has to issue one plain GET to that device's URL. No body, no headers, no authentication beyond the token already in the URL.

curl "{{ (webhook_urls[0][1] if webhook_urls else webhook_base ~ '/ring/<token>?device=<id>') }}"

A 200 with {"ok": true} means the ring was accepted; the reply comes back immediately and the audio plays after it, so the caller is never left waiting for the clip. A duplicate arriving inside the debounce window answers {"ok": false}, which is normal and not an error. Press the bell (or run the curl) and watch the Audit page for a chime entry.
