**Entry points:** `app/main.py` (ASGI, lifespan starts scheduler + watchers) · `/ring/{token}` webhook · APScheduler cron · 4 CLI probe scripts (`app/cli_*.py`).

**Trust boundaries:** the session-cookie login, the unauthenticated `/ring/{token}` webhook, 30 form POST endpoints, 2 file-upload paths, and the admin-supplied forward URL.

## Phase 3 — Executive Summary

### Maintainability Score: **62 / 100**

This is markedly better than a typical "vibe-coded" prototype — the domain reasoning is genuinely good, the comments explain *why* rather than *what*, `date_logic.py` is a properly isolated pure module, and 149 passing tests cover the schedule-resolution rules well. What holds it back is that the boundaries the design implies are not actually enforced anywhere: blocking network calls sit in `async def` handlers on a single-worker event loop, the template layer reaches into the database, cached device credentials silently go stale after an edit, and the browser-facing trust boundary has an open redirect, plaintext password comparison, and no CSRF protection on any of its 30 mutating forms.

**Scoring breakdown:** Domain modelling 16/20 · Testing 14/20 · Security 8/20 · Concurrency & reliability 10/20 · Hygiene & tooling 14/20.

### The five things to fix first

1. **Open redirect on login** (`auth.py:27`) — confirmed live, 4-line fix.
2. **Blocking I/O in `async def`** (`devices.py`, `dashboard.py`) — one unreachable DoorBird freezes the entire UI.
3. **Stale watcher credentials** (`ring_watcher.py:330`) — confirmed: editing a device does nothing until restart.
4. **Password handling** (`security.py:21`) — plaintext `==`; `passlib[bcrypt]` is a declared dependency that is never imported.
5. **Unpinned dependencies** (`Dockerfile:19-23`) — the dependency list is duplicated out of `pyproject.toml` with `>=`-only bounds and no lockfile; two builds a week apart are not the same image.

## Prioritised Remediation Plan

### Sprint 1 — Security & correctness (must land before any deployment beyond the author's LAN)

1. Fix the open redirect in `auth.py` — validate `next` is a same-site path. *(~4 lines)*
2. Hash the admin password with the already-installed passlib; constant-time username compare; refuse the `.env.example` default at boot.
3. Wrap the three blocking `async def` routes in `run_in_threadpool`.
4. Fingerprint watcher credentials so `refresh()` recreates stale watchers.
5. Add CSRF tokens to all 30 form POSTs; make logout a POST.
6. Enforce the upload size cap and stream uploads to disk in chunks.
7. Remove the device password from the `curl` argv.

### Sprint 2 — Reliability

8. `PRAGMA journal_mode=WAL`; serialise background writes.
9. Give the monitor stream a read timeout so `stop()` actually stops; `join()` with a timeout.

## What This Codebase Gets Right

Worth recording, because a refactor should not destroy it:

- **`app/date_logic.py`** is a genuinely well-factored pure module — no I/O, no globals, total ordering on tie-breaks, and thoroughly tested. It is the model the rest of the codebase should follow.
- **The comments explain intent, not mechanism.** `entrypoint.sh` on Synology uid ownership, `conftest.py` on why `setdefault` once corrupted production data, `ring_hook.py` on why the relay must not queue behind audio — this is institutional memory that survives the author, and it is rare.
- **The domain modelling is sound.** Separating `KIND_CHIME` from `KIND_AUTO_RESPONSE` at the data layer, so a delivery message can never be wired to the doorbell, is exactly the right call made at the right level.
- **The `_status_code` / retry handling around `audio-transmit.cgi`** encodes hard-won knowledge of a device that answers 204 and 503 for meaningfully different reasons, with error messages that tell the user what to actually do.
- **149 passing tests** on a personal project, including end-to-end page rendering, is far above the norm for this class of codebase.

The gap is not one of care. It is that the boundaries the design clearly has in mind are not enforced by anything — no CI, no types at the edges, no gate between "the author knows the rule" and "the code obeys it".
