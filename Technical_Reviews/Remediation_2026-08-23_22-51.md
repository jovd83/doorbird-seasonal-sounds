## Sprint 1 — Security & correctness

| # | Item | What changed | Proof |
| :-- | :--- | :--- | :--- |
| 1 | Open redirect | `safe_next()` restricts `?next=` to same-site paths, rejecting `//host`, `/\host` and encoded variants | 11 tests incl. end-to-end |
| 2 | Password handling | Replaced plaintext `==` with **stdlib scrypt** (`app/passwords.py`), constant-time username compare, per-IP lockout after 8 failures, boot refused on the placeholder password | 8 tests |
| 3 | Blocking `async def` | `test_device`, `apply_device_now`, `apply_now` moved to `run_in_threadpool` | route-source assertion |
| 4 | Stale watcher credentials | Watchers carry a credential fingerprint; `refresh()` retires any that drifted | 8 lifecycle tests |
| 5 | CSRF | Token on all 29 forms + login; `require_csrf` on every mutating router; logout is now POST | 6 tests, incl. one asserting every rendered form carries a token |
| 6 | Unbounded uploads | Streamed to disk in 64 KiB chunks with a hard cap, rolled back on failure | 10 tests, incl. a tripwire proving the read stops early |
| 7 | Credentials in argv | curl reads them from **stdin** via `--config -`, with escaping | test asserts the password never appears in any argv |

**On passlib:** the audit suggested using the already-declared `passlib[bcrypt]`. It turned out to be *unusable* — passlib 1.7.4 (2020) cannot drive bcrypt 5.x, which is what the unpinned Dockerfile resolved. Its backend probe fails on `bcrypt.__about__` and its self-test trips bcrypt's 72-byte limit. I dropped the dependency and used stdlib `scrypt`: one fewer dependency, no C-extension compatibility risk, no length ceiling. A 5 000-character password is now handled rather than causing a 500.

## Two bugs found while verifying, not in the original audit

**A lost `FERNET_KEY` crashed the app at boot.** Restoring a database into a container with a different key made `Fernet.decrypt` raise a bare `binascii.Error` out of `ring.start()`; the lifespan blew up and the container exited with no usable explanation. `decrypt` now raises a named `UndecryptableSecret`, and one unreadable device is isolated — its listener does not start, the reason is recorded against the device, and every other door station carries on.

**A pre-existing flaky test.** `test_consecutive_rings_play_different_members` failed **6.3% of the time** by chance — measured over 200 000 simulated runs, not guessed. With three collection members and six draws, "every member was used" genuinely fails that often. Fixed by making the RNG injectable and seeding it, which also addresses the audit's untestable-global-state finding.

I also found that `probe.html` referenced `r.POST` and `r.GET_excerpt` — dict keys the probe has **never** produced, so two table columns had rendered blank for every user. The dataclass conversion surfaced it; the template now matches what the code emits.

## What I did not do, and why

**`ruff format`.** It would rewrite 52 files. Several — the icon table and NAV list in `templating.py` — are hand-aligned because they read as tables. Adopting a formatter is a reasonable choice, but it is a style decision for you to make in its own commit, not something to smuggle in behind a lint gate. The CI file says so where the step would have gone.

**Foreign-key enforcement.** Explained above; needs a table rebuild, so it belongs with a future Alembic revision rather than a connect hook.

## Two things that need your attention

1. **`ADMIN_PASSWORD` still works but warns.** Existing installs keep running unchanged. Generate a hash with `python -m app.hash_password` and switch to `ADMIN_PASSWORD_HASH` when convenient.
2. **`SESSION_HTTPS_ONLY` defaults to 0.** Correct for the usual plain-HTTP LAN setup. If you ever put this behind a TLS proxy, set it to 1.
